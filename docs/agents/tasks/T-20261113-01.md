## Objetivo

Tornar o webhook Stripe idempotente e corrigir a criação de cafes órfãos.

Dois problemas identificados no log de 11/11 21:15:

1. **Idempotência**: Se o Stripe reenvia o mesmo evento (retry ou reenvio manual), o handler criava uma segunda subscription — ou tentava criar um segundo user com o mesmo e-mail, gerando `23505 (users_email_key)`. O catch respondia 200, então o Stripe não reenviava para corrigir, mas também não sabia que havia dado erro.

2. **Cafe órfão**: Quando a inserção do user falha por `23505`, o cafe já tinha sido inserido (IDs 5 e 6 no ambiente de teste). O catch engolia o erro com 200, deixando cafes sem user nem subscription.

As correções aplicadas (patch T-20261113-01):

- **Idempotência por subscription_id**: Antes de qualquer criação, verifica se `stripe_subscription_id` já existe em `subscriptions`. Se sim, responde `{"received":true,"duplicate":true}` e encerra sem criar nada.
- **Returning customer**: Se `tenant_id=0` e o e-mail já existe em `users`, reutiliza o `tenant_id` existente sem criar cafe nem user novos.
- **Limpeza de cafe órfão**: Se a inserção do user falhar, deleta o cafe recém-criado antes de lançar o erro.
- **Guard "no tenant resolved"**: Se após todos os caminhos `tenantId` ainda for ≤ 0, responde com warning em vez de gravar subscription sem tenant.
- **500 no catch**: O catch agora retorna HTTP 500 para que o Stripe faça retry automaticamente. Seguro porque o handler é idempotente.
